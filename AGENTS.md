# Collaboration instructions for AI-assisted studio work

This repository is a **creative research harness**, not an invitation to generate a finished video whenever a prompt sounds exciting.

## Entering the project

1. Read [README.md](README.md), [STATUS.md](STATUS.md), [the brick protocol](harness/BRICK_PROTOCOL.md), and [decisions](harness/DECISIONS.md).
2. Read the specific story's `README.md` and latest artifact. Check [open questions](harness/OPEN_QUESTIONS.md).
3. State the current brick and its author-approval boundary before deriving new work.
4. Read relevant original research provinces and the Stage 02 evaluation ledger. Treat force labels as candidate tools, not established universal laws.
5. Do not jump to a prompt, storyboard or rendered video before meaning and treatment gates have been deliberately passed.

## How to work

- Be **source-faithful**. Distinguish exact author statements, cited research, inference, unresolved uncertainty, and creative invention.
- Work on **one meaningful brick** at a time. Show alternatives and why one survives.
- Never silently replace the user's claim to suit an attractive AI-generated scene. Preserve the exact seed: "Having more information does not necessarily mean having more direction."
- Keep the engraved monochrome style benchmark separate from the story's subject. An astronaut is **not** prescribed.
- AI-first image-to-video remains the planned visual workflow. 2.5D/compositing are optional supporting techniques; editable 3D is not a project objective.
- Do not treat an unopposed draft or impressive output as approval. Record decisions with names, status, scope and revision trigger.
- When a workflow changes, update [workflow history](harness/WORKFLOW_HISTORY.md), the decision log if relevant, and the affected project status or handoff.
- When a brick closes, update `STATUS.md`, the affected story artifacts, open questions and a receipt. A commit alone is not a receipt.

## Public repo safety

Never copy private KIRA source materials, personal/private chats, confidential work, credentials or unrelated project documents into this public repository. Do not commit external reference art or generated-media binaries without rights review and a deliberate publication decision.
