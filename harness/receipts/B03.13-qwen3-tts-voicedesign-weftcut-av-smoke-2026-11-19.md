## Python environment boundary

Working video ComfyUI portable Python 3.13 has `transformers 5.21.0`, `numpy 2.5.4`, and `torch 2.14.1+cu130`. Qwen's Python package `qwen-tts 0.1.1` expects `transformers 4.57.3`; its `librosa/numba` chain is incompatible with the currently installed NumPy 2.5.

Rather than downgrade or alter the ComfyUI environment, project-local overlay packages were installed to:

`Documents/NOUSCERA/env/qwen3_site/`

Including `transformers 4.57.3`, `huggingface_hub 0.36.2`, `tokenizers 0.22.2`, `accelerate 1.12.0`, `numpy 2.3.5`, `qwen-tts 0.1.1` and required audio support packages. The overlay is added to the process `sys.path` only in the narration runner.

The embedded Python's own versions were rechecked after installation and remain `transformers 5.21.0`, `numpy 2.5.4`. ComfyUI 0.45.0 responded to `/system_stats` afterward. Its currently loaded `--disable-all-custom-nodes` server does not activate the Qwen extension. The Qwen Comfy custom-node source code and three-node VoiceDesign JSON are present locally but its in-app custom-node operation remains **untested**. Successful TTS inference uses the isolated standalone local Python route. Missing SoX binary and flash-attn were only warnings during this smoke test.
